`@sluby/sdk` is the TypeScript client for the Sluby REST API. It wraps every request in typed methods, uploads files over tus, verifies webhook signatures and opens the browser session that streams video straight from Sia. For a walkthrough, start with [Upload videos from your app](/developers/guides/upload).

## Install [#install]

```bash
npm install @sluby/sdk
```

## Package [#package]

| Fact           | Value                                                                                                      |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| Version        | This page describes `@sluby/sdk` 0.2.1                                                                     |
| Module formats | ESM (`import`) and CommonJS (`require`), each with its own type declarations                               |
| Entry points   | One: `@sluby/sdk`. There are no subpath exports.                                                           |
| Node.js        | `^20.16.0 \|\| >=22.3.0` (the `engines` field)                                                             |
| Browsers       | Every REST method, uploads and `verifyRequestAsync` run in a browser. `client.sia` runs only in a browser. |
| HTTP           | The global `fetch`. There is no option to pass your own.                                                   |
| Dependencies   | `tus-js-client` for uploads, `@siafoundation/sia-storage` for direct-from-Sia playback                     |
| Side effects   | None (`"sideEffects": false`)                                                                              |

The Sia storage SDK is a WebAssembly module. The client imports it the first time `client.sia` connects (`connect()`, `prepare()` or `resolveObjectId()`), so code that never touches `client.sia` never loads it.

## SlubyConfig [#slubyconfig]

```ts
interface SlubyConfig {
  baseUrl: string;
  apiKey?: string;
  credentials?: RequestCredentials;
  deliveryBaseUrl?: string;
  sia?: SiaViewerConfig;
  timeoutMs?: number;
}
```

| Option            | Type                 | Default   | Behavior                                                                                                                                                                                                                                                           |
| ----------------- | -------------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `baseUrl`         | `string`             | required  | The origin of your Sluby server, such as `https://sluby.example.com`. The SDK appends the `/api/v1/...` paths and removes trailing slashes.                                                                                                                        |
| `apiKey`          | `string`             | none      | Sent as `Authorization: Bearer <apiKey>` on every API request and every upload request. The public share map request of `client.sia` never carries it. Leave it out in a browser app on the same origin as the API: requests then carry the Studio session cookie. |
| `credentials`     | `RequestCredentials` | not set   | Passed to `fetch` for API requests. With `'include'`, uploads also send cookies cross-origin. Set it only when a cookie session crosses origins.                                                                                                                   |
| `deliveryBaseUrl` | `string`             | `baseUrl` | The origin the SDK resolves playback URLs against: `playback.streamUrl`, `playback.getUrl`, `playback.getSignedUrl` and relative `src` values in `client.sia`. The SDK removes trailing slashes.                                                                   |
| `sia`             | `SiaViewerConfig`    | none      | The viewer identity for direct-from-Sia playback. When set, `client.sia` is a [`SiaSession`](#sia). When not set, `client.sia` is `undefined`.                                                                                                                     |
| `timeoutMs`       | `number`             | none      | Rejects any API request that has not finished, headers and body, within this many milliseconds, with a [`TimeoutError`](#errors). It does not apply to uploads.                                                                                                    |

The constructor throws an `Error` when:

| Condition                                  | Message                                                                                |
| ------------------------------------------ | -------------------------------------------------------------------------------------- |
| `apiKey` is set to an empty string         | `SlubyClient apiKey must be non-empty when provided; omit it to use a cookie session.` |
| `baseUrl` is empty                         | `SlubyClient requires a non-empty baseUrl.`                                            |
| `timeoutMs` is not a finite number above 0 | `SlubyClient timeoutMs must be a positive number of milliseconds.`                     |

### SiaViewerConfig [#siaviewerconfig]

The publishable, low-privilege Sia identity a browser uses to download shared objects. [Stream from Sia in the browser](/self-hosting/direct-playback) shows how to create one.

| Field         | Type     | Default                              | Behavior                                                          |
| ------------- | -------- | ------------------------------------ | ----------------------------------------------------------------- |
| `indexerUrl`  | `string` | required                             | The indexer the viewer connects to, such as `https://sia.storage` |
| `appId`       | `string` | required                             | 32 bytes as 64 hex characters, with or without `0x`               |
| `appKey`      | `string` | required                             | 32 bytes as 64 hex characters, with or without `0x`               |
| `name`        | `string` | `Sluby Player`                       | App name shown to the indexer                                     |
| `description` | `string` | `Sluby direct-from-Sia video player` | App description shown to the indexer                              |
| `serviceUrl`  | `string` | `indexerUrl`                         | App service URL shown to the indexer                              |

### Request behavior [#request-behavior]

- Request bodies go out with the API's snake_case field names. Responses come back mapped to the camelCase types on this page.
- Every method that takes `options` accepts `signal?: AbortSignal`. When the signal fires, the call rejects with an [`AbortError`](#errors) whose `cause` is the signal's reason.
- The SDK reads the whole response body before it resolves, so `signal` and `timeoutMs` cover the body too.
- A response outside 200 to 299 rejects with the [error class for its status](#errors).
- A network failure rejects with the `TypeError` that `fetch` threw, not a `SlubyError`.
- The SDK does not retry REST requests. Uploads retry on their own (see `retryDelays` in [UploadFileOptions](#uploadfileoptions)).

The endpoint decides which [scope](/developers/reference/api-conventions#scopes) a request needs. Each method below links to its endpoint page.

## client.uploads [#uploads]

```ts
class UploadManager {
  upload(file: UploadInput, options: UploadOptions): AssetUploadHandle;
  getStatus(uploadId: string, options?: RequestOptions): Promise<UploadSession>;
  cancel(uploadId: string, options?: RequestOptions): Promise<void>;
}

type UploadInput = Blob | Uint8Array;
```

| Method      | Request                                                                                                                                                                            | Returns                                                                  |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `upload`    | tus upload to [`POST /api/v1/uploads`](/developers/reference/api/uploads/post-uploads), then [`PATCH`](/developers/reference/api/uploads/patch-uploads-id) requests for the chunks | An [`AssetUploadHandle`](#assetuploadhandle) right away, without waiting |
| `getStatus` | [`GET /api/v1/uploads/{uploadId}`](/developers/reference/api/uploads/get-uploads-id)                                                                                               | `UploadSession`                                                          |
| `cancel`    | [`DELETE /api/v1/uploads/{uploadId}`](/developers/reference/api/uploads/delete-uploads-id)                                                                                         | Nothing                                                                  |

`upload()` takes a `File` or `Blob` in the browser, and a `Buffer`, `Uint8Array` or `Blob` (for example from `fs.openAsBlob`) in Node.js. It does not take Node.js streams. Each call creates one video asset, unless it resumes an unfinished upload (see `resume` below). The upload runs as a single tus stream.

### UploadOptions [#uploadoptions]

`UploadOptions` is [`UploadFileOptions`](#uploadfileoptions) plus the fields of the new video. The SDK sends them as tus metadata.

| Field         | Type                    | Default    | tus metadata key |
| ------------- | ----------------------- | ---------- | ---------------- |
| `title`       | `string`                | required   | `title`          |
| `description` | `string`                | `''`       | `description`    |
| `accessTier`  | `'public' \| 'private'` | `'public'` | `accessTier`     |

The SDK also sends `filename` (the `File`'s name, or `video`) and `filetype` (the `Blob`'s type, or an empty string).

### UploadFileOptions [#uploadfileoptions]

| Field         | Type                                                                   | Default                 | Behavior                                                                                                                                                                                                    |
| ------------- | ---------------------------------------------------------------------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chunkSize`   | `number`                                                               | `10485760` (10 MiB)     | Bytes per tus `PATCH` request                                                                                                                                                                               |
| `retryDelays` | `number[]`                                                             | `[0, 1000, 3000, 5000]` | Milliseconds to wait before each tus retry                                                                                                                                                                  |
| `onProgress`  | `(percent: number, bytesUploaded: number, bytesTotal: number) => void` | none                    | `percent` is `Math.round(bytesUploaded / bytesTotal * 100)`. Not called while `bytesTotal` is 0.                                                                                                            |
| `onSuccess`   | `() => void`                                                           | none                    | Called once when every byte is uploaded                                                                                                                                                                     |
| `onError`     | `(error: Error) => void`                                               | none                    | Called with the same `SlubyError` the handle rejects with                                                                                                                                                   |
| `resume`      | `boolean`                                                              | `true`                  | In a browser, resumes an unfinished upload of the same file, with the same metadata, by the same key, from an earlier page load. A finished upload is never resumed. A `Uint8Array` input is never resumed. |
| `signal`      | `AbortSignal`                                                          | none                    | Aborts the upload like `handle.abort()`                                                                                                                                                                     |

Before it resumes a stored upload, the SDK sends a `HEAD` to it and resumes only when the server reports `Upload-Offset` below `Upload-Length`.

### AssetUploadHandle [#assetuploadhandle]

```ts
type AssetUploadHandle = Promise<void> & {
  assetId: Promise<string>;
  uploadId: Promise<string>;
  pause: () => Promise<void>;
  resume: () => void;
  abort: () => Promise<void>;
  readonly isPaused: boolean;
};
```

| Member         | Behavior                                                                                                                                                                                                                                           |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `await handle` | Resolves when every byte is uploaded. Processing then continues on the server: use [`assets.waitForReady`](#assets) to wait for it.                                                                                                                |
| `assetId`      | The id of the asset the upload created, available as soon as the server creates the upload                                                                                                                                                         |
| `uploadId`     | The last path segment of the tus upload URL, the id `getStatus` and `cancel` take                                                                                                                                                                  |
| `pause()`      | Stops sending and keeps the partial upload                                                                                                                                                                                                         |
| `resume()`     | Continues a paused upload from where it stopped                                                                                                                                                                                                    |
| `abort()`      | Stops sending, terminates the upload on the server (which discards the asset it created) and rejects the handle, `assetId` and `uploadId` (those not yet settled) with `AbortError('Upload aborted.')`. Does nothing once the upload has finished. |
| `isPaused`     | Whether the upload is paused                                                                                                                                                                                                                       |

The handle, `assetId` and `uploadId` reject with the [error class](#errors) for the HTTP status of a failed tus request (the tus error is on `cause`), or with a `SlubyError` whose message starts with `Upload failed:` for any other failure.

### update and If-Match [#update-if-match]

Pass `ifMatch` to apply the edit only if nobody changed the asset since you read it. Pass the asset as you read it, or an ETag string. `assetEtag(asset)` builds the ETag the server uses: `asset.updatedAt` in milliseconds since the epoch, in double quotes. It throws a `TypeError` when `updatedAt` is not a date.

When the asset changed, `update` rejects with a `ConflictError` whose `statusCode` is `412` and whose `current` is the asset as the server has it now.

```ts
import { ConflictError } from '@sluby/sdk';

try {
  await client.assets.update(asset.id, { title: 'New title' }, { ifMatch: asset });
} catch (err) {
  if (err instanceof ConflictError && err.current) {
    // the asset changed on the server; err.current is the version there now
  }
}
```

### waitForReady [#waitforready]

| Option         | Default               | Behavior                                                                                                                                           |
| -------------- | --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pollInterval` | `5000`                | Milliseconds between reads                                                                                                                         |
| `timeout`      | `600000` (10 minutes) | Longest wait in milliseconds. The asset is read at least once, even with `timeout: 0`.                                                             |
| `signal`       | none                  | Stops polling and rejects with an `AbortError`: `Stopped waiting: the signal was aborted.` between reads, `The request was aborted.` during a read |

| Outcome         | Result                                                                                             |
| --------------- | -------------------------------------------------------------------------------------------------- |
| Status `ready`  | Resolves with the asset                                                                            |
| Status `failed` | Rejects with `ProcessingFailedError`, whose `asset` is the asset as last read                      |
| Timeout         | Rejects with `TimeoutError('Timed out after <timeout>ms waiting for asset <id> to become ready.')` |

```ts
class PlaybackManager {

    videoAssetId: string,

```

| Method         | Request                                                                                                                                                   | Returns                                                                                  |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `streamUrl`    | None. It builds the URL of [`GET /v1/stream/{id}/master.m3u8`](/developers/reference/api/delivery/get-stream-videoassetid-master-m3u8) without a request. | `<deliveryBaseUrl>/v1/stream/<id>/master.m3u8` for an asset id or a `pb_...` playback id |

| -------------------------- | ---------------- | -------------------------------------------------------------------------- |

## client.sessions [#sessions]

## client.reconciliation [#reconciliation]

```ts
class ReconciliationManager {
  latest(options?: RequestOptions): Promise<ReconciliationReport>;
  run(options?: RequestOptions): Promise<ReconciliationTrigger>;
}
```

| Method   | Request                                                                                               | Returns                                                                                               |
| -------- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `latest` | [`GET /api/v1/reconciliation`](/developers/reference/api/reconciliation/get-reconciliation)           | The latest finished storage check. Rejects with `NotFoundError` before the first check finishes.      |
| `run`    | [`POST /api/v1/reconciliation/run`](/developers/reference/api/reconciliation/post-reconciliation-run) | `{ enqueued, alreadyPending }`. Only an admin can run it; anyone else gets a `PermissionError` (403). |

`ReconciliationReport` is a union on `scope`:

- `scope: 'deployment'` (for an admin): the whole deployment, with `dbObjectCount`, `indexerObjectCount`, `inSyncCount`, `orphanCount`, `orphanedIds` and `errorMessage`.
- `scope: 'account'` (for a caller that is not an admin): the missing objects of the workspace's videos, without the deployment-wide counts.

Both carry `id`, `startedAt`, `finishedAt`, `createdAt`, `status` (`'ok' | 'drift' | 'failed'`), `missingCount`, `missingIds` and `missingObjects` (each `{ objectId, videoAssetId, title }`). [Deletion and reconciliation](/developers/concepts/deletion-and-reconciliation) explains the check.

## client.webhooks [#webhooks]

```ts
class WebhookManager {
  verifyRequest(
    payload: string,
    headers: WebhookHeaders,
    secret: string,
    options?: VerifyRequestOptions,
  ): boolean;
  verifyRequestAsync(
    payload: string,
    headers: WebhookHeaders,
    secret: string,
    options?: VerifyRequestOptions,
  ): Promise<boolean>;
  verifySignature(payload: string, signature: string, secret: string): boolean;
  verifySignatureAsync(payload: string, signature: string, secret: string): Promise<boolean>;
  parseEvent(payload: string): WebhookEvent;
}

type WebhookHeaders =
  { get(name: string): string | null } | Record<string, string | string[] | undefined>;

interface VerifyRequestOptions {
  toleranceSeconds?: number; // default 300
  now?: number; // current time in Unix seconds, default the clock
}

const DEFAULT_WEBHOOK_TOLERANCE_SECONDS = 300;
```

`WebhookManager` needs no credentials. Use it through any client, or construct it on its own with `new WebhookManager()`.

| Method                 | Runs on                                             | Behavior                                                                                                                                                          |
| ---------------------- | --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `verifyRequest`        | Node.js                                             | `true` when `X-Sluby-Signature-V1` is the hex HMAC-SHA256 of `<X-Sluby-Timestamp>.<payload>` under `secret` and the timestamp is within `toleranceSeconds` of now |
| `verifyRequestAsync`   | Web Crypto (browsers, edge runtimes, Deno, Node.js) | Same check as `verifyRequest`                                                                                                                                     |
| `verifySignature`      | Node.js                                             | `true` when `signature` (hex, either case) is the HMAC-SHA256 of `payload` under `secret`. Compares in constant time.                                             |
| `verifySignatureAsync` | Web Crypto                                          | Same check as `verifySignature`                                                                                                                                   |
| `parseEvent`           | Anywhere                                            | Parses the body into a `WebhookEvent`                                                                                                                             |

Details:

- Pass the raw request body as `payload`, exactly as received, before any JSON parsing.
- `headers` takes a Fetch `Headers` object or a Node.js `req.headers` record. Header names match case-insensitively, and for an array the SDK uses the first value.
- The timestamp must be 1 to 12 digits. A missing header, a malformed timestamp or one outside the tolerance returns `false`.
- `verifySignature` throws where `process.getBuiltinModule` is missing (outside Node.js): `Synchronous signature verification needs Node.js 20.16+ or 22.3+ (process.getBuiltinModule). Use verifySignatureAsync() in browser or edge environments.` `verifyRequest` throws the same error once the headers pass the timestamp checks.
- `parseEvent` throws `Invalid webhook payload: missing required "event" or "timestamp" field.` when either is not a string, and throws the `SyntaxError` of `JSON.parse` for a body that is not JSON. It keeps `id` only when it is a string and sets `data` to `{}` when it is missing.

```ts
import { WebhookManager } from '@sluby/sdk';

const webhooks = new WebhookManager();

// rawBody: the request body as a string; headers: req.headers
if (webhooks.verifyRequest(rawBody, headers, process.env.SLUBY_WEBHOOK_SECRET!)) {
  const event = webhooks.parseEvent(rawBody);
  console.log(event.id, event.event, event.data.video_asset_id);
}
```

`WebhookEvent` is `{ id?: string; event: WebhookEventName | (string & {}); timestamp: string; data: Record<string, unknown> }`. `data` keeps the snake_case keys of the payload. The headers, signature scheme and every payload are on [Webhook events](/developers/reference/webhook-events).

## client.sia [#sia]

`client.sia` is a `SiaSession` when the client was created with [`sia`](#siaviewerconfig), and `undefined` otherwise. It runs only in a browser. `@sluby/player` drives it; call it yourself only when you build your own player. [Playback and delivery](/developers/concepts/playback) explains direct-from-Sia playback.

```ts
class SiaSession {
  static readonly MAX_CACHED_OBJECTS = 64;
  constructor(fetchFn: FetchFn, config: SiaViewerConfig, transport?: SiaSessionTransport);
  connect(): Promise<void>;
  prepare(assetId: string, source?: SiaShareSource): Promise<void>;
  getShareMap(
    assetId: string,
    source?: SiaShareSource,
    options?: { renew?: boolean },
  ): Promise<SiaShareMap>;
  shareMapUrl(assetId: string, src: string): string;
  masterObjectId(assetId: string, source?: SiaShareSource): Promise<string>;
  resolveObjectId(assetId: string, objectId: string, source?: SiaShareSource): Promise<SiaObject>;
  download(object: SiaObject, options?: SiaDownloadOptions): ReadableStream;
  dispose(): void;
}

interface SiaShareSource {
  src?: string;
}

interface SiaDownloadOptions {
  offset?: number;
  length?: number;
}

function publicShareMapUrl(assetId: string, src: string): string;
```

`FetchFn` is not exported. Use the session `SlubyClient` creates rather than constructing one.

### Share map source [#share-map-source]

Every method that needs an asset's share map takes an optional `source`:

| `source`                                                                                                                                                                        | Share map request                                                                                                                   | Credentials                                                 |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| `{ src }`, where `src` is the gateway playback URL being played (`/v1/stream/{id}/master.m3u8` or `/v1/objects/{id}`, signed or not, absolute or relative to `deliveryBaseUrl`) | [`GET /v1/share/{id}`](/developers/reference/api/delivery/get-share-id) on the delivery base, with the `expires` and `sig` of `src` | None, so a page without an API key can play direct from Sia |
| Not set                                                                                                                                                                         | [`GET /api/v1/playback/{id}/share`](/developers/reference/api/playback/get-playback-id-share)                                       | The client's API key or session                             |

### Methods [#sia-methods]

| Method                                        | Behavior                                                                                                                                                                                                                                                                                                                                                                               |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `connect()`                                   | Loads the WebAssembly SDK and connects to the indexer with the viewer app key. Resolves once connected; later calls reuse the connection. A failed attempt is not cached, so the next call tries again. Rejects when the app id or key is not 64 hex characters, or when the app key is not registered with the indexer.                                                               |
| `prepare(assetId, source?)`                   | `connect()`, then loads the asset's share map                                                                                                                                                                                                                                                                                                                                          |
| `getShareMap(assetId, source?, options?)`     | Fetches the share map without caching it. `renew: true` adds `renew=1` to a public request, so the server does not count another play. Rejects with a `SlubyError` when the answer has no valid `expires_at`.                                                                                                                                                                          |
| `shareMapUrl(assetId, src)`                   | The public share map URL for `src`, after resolving a relative `src` against `deliveryBaseUrl`                                                                                                                                                                                                                                                                                         |
| `masterObjectId(assetId, source?)`            | The object id of the asset's HLS master playlist, from the cached share map                                                                                                                                                                                                                                                                                                            |
| `resolveObjectId(assetId, objectId, source?)` | A downloadable handle for one object of the asset. Cached per asset and object, at most `MAX_CACHED_OBJECTS` (64), least recently used dropped first. Fetches a fresh share map once when the object is missing from it, or when its share URL fails less than 60 seconds before the map's expiry or later. Rejects with `NotFoundError` when the map has no share URL for the object. |
| `download(object, options?)`                  | A `ReadableStream` of the object's bytes from Sia, from `offset` for `length` bytes. Throws when called before the session is connected.                                                                                                                                                                                                                                               |
| `dispose()`                                   | Frees every resolved object and the WebAssembly SDK and forgets the share maps. The session stays usable: the next call connects again.                                                                                                                                                                                                                                                |

The session caches each share map per asset and source, and fetches a new one when the cached map is missing, expired, or within 60 seconds of its `expiresAt`. A map that arrived already inside those 60 seconds stays in use until it expires. A refetch of a map the session already held adds `renew=1` to a public request.

`publicShareMapUrl(assetId, src)` builds the public share map URL for an absolute `src`. The share id is the `{id}` in a `/v1/stream/{id}/master.m3u8` URL, or `assetId` for a `/v1/objects/{id}` URL. It throws when `src` is neither.

`SiaShareMap` is `{ masterObjectId: string; shares: Record<string, string>; expiresAt: string }`, where `shares` maps each object id (hex) to its `sia://` share URL.

## Errors [#errors]

Every error the SDK creates extends `SlubyError`, which extends `Error`. Check classes with `instanceof`.

| Class                   | `statusCode`        | Thrown when                                                                                                                                                                         | Extra fields                                                                           |
| ----------------------- | ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `SlubyError`            | HTTP status, or `0` | Base class. Thrown directly for a status without its own class (such as 500 or 502), for a 2xx response whose body is not JSON, and for an upload failure without an HTTP response. | `responseBody?: string`, `cause`                                                       |
| `ValidationError`       | `400` or `422`      | The request is malformed or a value is invalid                                                                                                                                      |                                                                                        |
| `AuthenticationError`   | `401`               | The key or session is missing, wrong, revoked or expired                                                                                                                            |                                                                                        |
| `PermissionError`       | `403`               | The caller is known but not allowed: a key without the needed scope, a member without the needed role, or a signed URL that is invalid or expired                                   |                                                                                        |
| `NotFoundError`         | `404` or `410`      | The resource does not exist, or no longer does (410)                                                                                                                                |                                                                                        |
| `ConflictError`         | `409` or `412`      | The resource is not in a state that allows the request (409), or an `update` with `ifMatch` found the asset changed (412)                                                           | `current?: VideoAsset` on a 412 from `assets.update`                                   |
| `RateLimitError`        | `429`               | The key or caller went over a [rate limit](/developers/reference/api-conventions#rate-limits)                                                                                       | `retryAfter?: number`, seconds from the `Retry-After` header (seconds or an HTTP date) |
| `TimeoutError`          | `0`                 | A request ran past `timeoutMs`, or `waitForReady` ran past its `timeout`                                                                                                            |                                                                                        |
| `AbortError`            | `0`                 | A `signal` fired, or `abort()` was called on an upload. `name` is `'AbortError'`, like the DOM's.                                                                                   | `cause`: the signal's reason                                                           |
| `ProcessingFailedError` | `0`                 | `waitForReady` read the asset as `failed`                                                                                                                                           | `asset: VideoAsset`                                                                    |

The `message` of an HTTP error is the `error` string of a JSON body, else its `message` string. For a body that is not JSON, it is the trimmed body text when that is one line under 200 characters and does not start with `<`. Otherwise it is the HTTP status text, else `Unknown API error`. The raw body is on `responseBody`. [Errors in API conventions](/developers/reference/api-conventions#errors) describes the error body the API sends.

A network failure is not a `SlubyError`: the SDK rethrows the `TypeError` from `fetch`. A `statusCode` of `0` marks an error raised in the client, not by the server.

```ts
import { SlubyError, RateLimitError } from '@sluby/sdk';

try {
  await client.assets.list();
} catch (err) {
  if (err instanceof RateLimitError) {
    console.log(`retry in ${err.retryAfter ?? 60} s`);
  } else if (err instanceof SlubyError) {
    console.log(err.name, err.statusCode, err.message);
  } else {
    throw err; // a network failure from fetch
  }
}
```
